# Types of Inheritance in C++ — Complete Notes

> Ye notes tumhare diye gaye poore code (6 types of inheritance) pe based hain — har type ki **definition, diagram, code walkthrough, aur analogy** ke saath. Last mein **Multipath Inheritance + Virtual Keyword** (sabse advanced part) bhi deeply cover kiya hai.

---

## 0. Inheritance Types — Overview

C++ mein inheritance **6 tarah ki** ho sakti hai, is baat pe depend karke ki **kitni classes hain aur unka aapas mein structure kaisa hai**:


| # | Type                | Structure                                                     |
| - | ------------------- | ------------------------------------------------------------- |
| 1 | Single Level        | Ek Parent → Ek Child                                         |
| 2 | Multilevel          | Grandparent → Parent → Child (chain)                        |
| 3 | Multiple            | Do (ya zyada) Unrelated Parents → Ek Child                   |
| 4 | Hierarchical        | Ek Parent → Multiple Children                                |
| 5 | Hybrid              | Upar wali types ka combination                                |
| 6 | Multipath (Diamond) | Ek Grandparent → 2 Parents → Wapas Ek Child mein milte hain |

---

## 1. Single Level Inheritance

**Definition:** Jab ek **Child class sirf ek hi Parent class** se properties inherit karti hai — sabse simple aur basic type.

```
Human (Parent)
   │
   ▼
Student (Child)
```

```cpp
class Human {
protected:
    string name;
    int age;
public:
    Human() { cout << "Hello I am Human constructor" << endl; }
    Human(string name, int age) {
        this->name = name;
        this->age = age;
    }
    void display() { cout << name << " " << age << endl; }
    void work() { cout << "I am working\n"; }
};

class Student : public Human {
    int roll_number, fees;
public:
    Student() { cout << "Hello mai hu student constructor" << endl; }
    Student(string name, int age, int roll_number, int fees) : Human(name, age) {
        this->roll_number = roll_number;
        this->fees = fees;
    }
    void display() {
        cout << name << " " << age << " " << roll_number << " " << fees << " " << endl;
    }
};
```

**Analogy:** Ye ek **bacche aur uske ek hi parent (jaise sirf father)** jaisa hai — bacche ko sirf usi ek insaan se properties milti hain, koi extra chain nahi hai.

### Important Concept — Function Hiding (Tumne Khud Noted Kiya)

Tumhare comment mein bilkul sahi point tha: *"2 fn same naam hai, lekin call ye wala nahi hoga, kyunki local scope mein dekhega, child apne mein dekhega, phir parent mein aayega — agar nahi mila to display mein Student wala hi chalega"*

```cpp
Human h;
h.display();       // Human::display() chalega (kyunki h Human hai)

Student A1(...);
A1.display();      // Student::display() chalega, Human::display() NAHI (kyunki Student apna khud ka display() define kar chuka)
```

**Rule:** Jab Child class ka koi function **Parent ke function ka naam repeat** karta hai (same naam), to ye **"Function Hiding"** kehlata hai — Child ka apna version **Parent ke version ko chhupa deta hai**. Compiler pehle **Child class ke andar dhundta hai**; agar mil gaya, to wahi use karega — Parent tak jaata hi nahi.

**Analogy:** Ye aisа hai jaise ghar mein pehle **apne kamre (Child scope)** mein cheez dhundhte ho; agar mil jaaye to wahi use kar lete ho. Sirf tab **doosre kamre (Parent scope)** mein jaate ho jab apne kamre mein na mile.

### Constructor Call Order (Pehle Se Discuss Kiya Concept)

```cpp
Student A1("yash", 21, 240, 180000);
// Output: Pehle "Human" ka parameterized constructor (implicitly via Human(name,age)) chalega
//         Fir Student ka apna constructor chalega
```

**Rule (jo tumne khud comment mein likha):***"pehle Human ka constructor chalega, kyunki wo parent hai, phir Student"* — Ye humne pehle **Destructor notes** mein bhi dekha tha (reverse order wala concept) — construction hamesha **Parent → Child** order mein hota hai.

## 2. Multilevel Inheritance

**Definition:** Jab inheritance ek **chain/layers** mein hoti hai — Grandparent → Parent → Child. Matlab ek class doosri se inherit karti hai, aur teesri class **usse (jo khud ek derived class hai)** aage inherit karti hai.

```
Person (Grandparent)
   │
   ▼
Employee (Parent, jo Person se inherit karta hai)
   │
   ▼
Manager (Child, jo Employee se inherit karta hai)
```

```cpp
class Person {
protected:
    string name;
    int age;
    void introduce() { cout << "Hello my name is :" << name << endl; }
};

class Employee : public Person {          // Person se inherit
protected:
    int salary;
public:
    void monthly_salary() { cout << "My Monthly Salary is:" << salary << endl; }
};

class Manager : public Employee {          // Employee se inherit (jo khud Person se inherit hai)
public:
    string department;
    Manager(string name, int salary, string department) {
        this->name = name;       // Person se aaya (via Employee)
        this->salary = salary;   // Employee se aaya
        this->department = department;
    }
    void work() {
        introduce();             // Person ka function, chain ke through mil gaya
        cout << "I am leading the department " << department << endl;
    }
};
```

**Key Insight:**`Manager` ke paas `Person` ke **`name`, `introduce()`** aur `Employee` ke **`salary`, `monthly_salary()`** dono **automatically available** hain — chahe unhone directly `Person` se inherit nahi kiya, balki **`Employee` ke through indirectly** mila.

**Access Note (tumne khud test kiya):**

```cpp
Manager A1("Yash", 1e8, "Founder/Ceo");
// A1.introduce();   // ❌ ERROR! introduce() PROTECTED hai — sirf class ke andar ya derived class ke MEMBER FUNCTIONS se call ho sakta hai, seedha object se nahi
A1.work();            // ✅ OK — kyunki work() ANDAR se introduce() ko call kar raha hai (Manager ka apna member function hai)
```

**Analogy:** Ye bilkul **family generations** jaisa hai — **Dada (Person) → Papa (Employee) → Beta (Manager)**. Beta ko Dada ki property (traits) seedhe nahi, balki **Papa ke through virasat (inheritance)** mein milti hai. Beta ke paas Dada aur Papa dono ki cheezein hain, chahe usne Dada se seedha kabhi baat na ki ho.

## 3. Multiple Inheritance

**Definition:** Jab ek **Child class do (ya zyada) Parent classes** se inherit karti hai, **aur ye Parent classes aapas mein related nahi hote** (ek doosre se inherit nahi karte — warna wo Multilevel ban jaata).

```
Engineer        Youtuber
    \              /
     \            /
      CodeTeacher
```

```cpp
class Engineer {
    void money() { cout << "Hello money\n"; }
public:
    string specilization;
    void work() { cout << "I have specialization in " << specilization << endl; }
    Engineer() { cout << " hello Engineer " << endl; }
};

class Youtuber {
public:
    int subscriber;
    void contentcreater() { cout << "I have a subscriber base of " << subscriber << endl; }
    Youtuber() { cout << "Hello Youtuber" << endl; }
};

class CodeTeacher : public Engineer, public Youtuber {   // DONO se inherit — comma se separate
public:
    string name;
    CodeTeacher(string name, string specilization, int subscriber) {
        this->name = name;
        this->specilization = specilization;   // Engineer se
        this->subscriber = subscriber;          // Youtuber se
    }
    void showcase() {
        cout << "My name is: " << name << endl;
        work();              // Engineer ka function
        contentcreater();    // Youtuber ka function
    }
};
```

**Constructor Call Order Note:** Jab `CodeTeacher A1(...)` banoge, to **dono Parent constructors (Engineer aur Youtuber) call honge, jis order mein wo `: public Engineer, public Youtuber` mein LIKHE gaye hain (left to right)** — Engineer pehle, phir Youtuber, phir CodeTeacher.

**Analogy:** Ye aisa hai jaise koi insaan **do alag-alag skills wale mentors (Engineer aur Youtuber, jo ek doosre se bilkul unrelated hain)** se seekh raha ho — ek se coding, doosre se content creation — aur khud in dono skills ko combine karke ek naya identity (**CodeTeacher**) bana raha ho.

## 4. Hierarchical Inheritance

**Definition:** Jab **ek hi Parent class se multiple Child classes** inherit karti hain — Single Level ka "reverse/expanded" version.

```
              Human (Parent)
             /            \
       Teacher          Student
```

```cpp
class Human {
protected:
    string name;
    int age;
public:
    Human() {};
    Human(string name, int age) {
        this->name = name;
        this->age = age;
    }
};

class Teacher : public Human {
    int salary;
public:
    Teacher(int salary, string name, int age) {
        this->salary = salary;
        this->name = name;
        this->age = age;
    }
    void display() { cout << name << " " << age << " " << salary << endl; }
};

class Student : public Human {
    int roll_number, fees;
public:
    Student(string name, int age, int roll_number, int fees) : Human(name, age) {
        this->roll_number = roll_number;
        this->fees = fees;
    }
    void display() {
        cout << name << " " << age << " " << roll_number << " " << fees << " " << endl;
    }
};
```

### Important Point Jo Tumne Khud Note Kiya (Constructor Rule)

**Tumhara comment:***"agar parent class mein parameterized constructor bana diya hai to usse use karna padega, kyunki ab uska default constructor compiler nahi banayega"*

**Ye ek VERY IMPORTANT C++ rule hai:**

* Agar tum khud **koi bhi constructor** (chahe parameterized ho) class mein likh dete ho, to compiler **apna khud ka default (empty) constructor generate karna band kar deta hai.**
* Isliye agar `Human` class mein sirf `Human(string name, int age)` hota (bina explicit `Human() {}` ke), to `Teacher` class (jo apne constructor mein `Human()` ko implicitly call karne ki koshish karta) **compile hi nahi hota** — kyunki `Human` ka koi default constructor exist hi nahi karta.
* **Isiliye tumne `Human()` ka ek khaali version explicitly bana diya** — taaki `Teacher`/`Student` bina explicitly `Human(name, age)` call kiye bhi safely ban sakein.

**Analogy:** Ye aisa hai jaise ek company (Base class) ka rule hai — *"agar tumne khud kabhi apna koi specific entry-process (constructor) define kiya, to company automatically ek generic/default entry-process nahi degi — tumhe explicitly ek generic waala bhi banana padega agar chahiye ho."*

**Analogy (Hierarchical):** Ye bilkul ek **Parent ke multiple bachche (Teacher, Student)** jaisa hai — dono ek hi Parent (Human) se common properties (`name`, `age`) paate hain, lekin har bachcha apni **alag identity aur extra properties** (Teacher → `salary`, Student → `roll_number`, `fees`) develop karta hai.

## 5. Hybrid Inheritance

**Definition:** Jab **do ya zyada inheritance types ko combine** kiya jaata hai — jaise Hierarchical + Multiple ek saath.

```
                Student        Male   Female
                 /  \          /         \
                /    \        /           \
              Boy -----------      Girl ----
         (Student+Male)        (Student+Female)
```

```cpp
class Student {
public:
    void print() { cout << "I am Student" << endl; }
};

class Male {
public:
    void Maleprint() { cout << " I am Male\n"; }
};

class Female {
public:
    void Femaleprint() { cout << " I am Female\n"; }
};

class Boy : public Student, public Male {   // Hierarchical (Student ke 2 children) + Multiple (Boy ke 2 parents)
public:
    void Boyprint() { cout << "I am Boy" << endl; }
};

class Girl : public Student, public Female {
public:
    void Girlprint() { cout << "I am Girl" << endl; }
};
```

Yahan:

* `Student` class **do bachchon (Boy, Girl)** ko de rahi hai → ye **Hierarchical** hissa hai.
* `Boy` khud **do parents (Student, Male)** se le raha hai → ye **Multiple** hissa hai.

Dono types **combine** hoke Hybrid ban gaye.

**Analogy:** Ye asal zindagi jaisa hai — koi bhi complex family tree sirf ek simple pattern follow nahi karta, usme **multiple relationships mix** hote hain — kuch log ek hi source se related hain (Hierarchical), aur kuch do alag sources se combine hoke bane hain (Multiple) — dono mila ke poora tree **Hybrid** banta hai.

## 6. Multipath Inheritance (Diamond Problem) — SABSE ADVANCED TOPIC

**Definition:** Jab ek class **do parents se inherit karti hai, jo dono khud ek hi common grandparent se inherit karte hain** — is structure ko **"Diamond Shape"** banati hai, isliye ise **"Diamond Problem"** bhi kehte hain.

```
                Human
               /      \
         Engineer     Youtuber
               \      /
             CodeTeacher
```

### Naam "Diamond Problem" Hi Kyu Pada?

**Haan, ye wahi hai** — Multipath Inheritance ko hi "Diamond Problem" bolte hain. Naam isliye pada kyunki agar tum inheritance ka structure diagram banao, to wo bilkul **heere (♦ diamond) ke shape** jaisa dikhta hai:

* **Top pe ek point** → `Human` (common grandparent/ancestor)
* **Beech mein do lines phailti hain** → `Engineer`, `Youtuber` (do parents)
* **Neeche wapas ek point pe milti hain** → `CodeTeacher` (common child)

Ye shape upar-neeche do points aur beech mein phaili hui do lines — bilkul **♦ diamond ki tarah** dikhta hai, isi wajah se naam **"Diamond Problem"** pada.

**Important Clarification — Ye Problem Kab Hi Aati Hai:** Ye specifically tab hi hoti hai jab **Multiple + Multilevel ka mix** ho — matlab jab **wahi ek common ancestor do alag-alag paths se ghoom ke wapas ek hi child mein mil jaaye.** Normal **Multiple Inheritance** (jaise agar `Engineer` aur `Youtuber` dono **unrelated** hote, koi common `Human` parent na hota) mein ye ambiguity problem **nahi** aati — wo sirf tab aati hai jab beech mein ek **shared/common base class** ho.

### 6.1 Problem Kya Hai? (Bina Virtual Ke)

```cpp
class Human {
public:
    string name;
    void display() { cout << "My name is " << name << endl; }
};

class Engineer : public Human { ... };   // apna khud ka Human ka COPY
class Youtuber : public Human { ... };   // apna khud ka Human ka ALAG COPY

class CodeTeacher : public Engineer, public Youtuber {
    CodeTeacher(...) {
        this->name = name;   // ❌ AMBIGUOUS ERROR!
    }
};
```

**Kya Ho Raha Hai:** Jab `CodeTeacher`, `Engineer` aur `Youtuber` dono se inherit karta hai, aur **dono ke paas apna-apna ALAG `Human` ka copy hai** (kyunki dono ne independently `Human` ko inherit kiya), to `CodeTeacher` ke andar **`name` ki DO copies** ban jaati hain:

* Ek `Engineer` ke through aayi `Human::name`
* Ek `Youtuber` ke through aayi `Human::name`

Jab tum sirf `this->name` likhte ho, **compiler confuse ho jaata hai — "KAUNSA name? Engineer wala ya Youtuber wala?"** — isliye **"Ambiguous" compile error** aata hai.

**Tumhara comment bilkul sahi tha:***"yahan name Engineer aur Youtuber dono ke paas se aayega, to ambiguous ka error aayega, ye pata nahi laga paa raha konsa name mein doon"*

```
                Human
               /      \
    Human's copy#1   Human's copy#2
    (via Engineer)   (via Youtuber)
               \      /
            CodeTeacher
       (confusion: DO 'name' variables hain!)
```

**Analogy:** Socho tumhare **Dada (Human)** hain. Tumhare **Papa** aur **Chacha (Engineer, Youtuber)** dono ko dada se **apni-apni alag property (copy)** mili — jaise dono ko alag-alag ek-ek similar ghadi mili (dono asli mein Dada ki ek hi tarah ki ghadi thi, lekin do alag physical copies ban gayi). Ab tum (CodeTeacher) dono se properties inherit kar rahe ho — jab koi poochta hai "Dada ki ghadi dikhao", to tumhare paas **do ghadiyan** hain — confusion ho jaata hai konsi asli "Dada ki ghadi" hai.

---

### 6.2 Solution — `virtual` Inheritance

```cpp
class Human {
public:
    string name;
    void display() { cout << "My name is " << name << endl; }
};

class Engineer : public virtual Human { ... };   // 'virtual' keyword lagaya
class Youtuber : public virtual Human { ... };   // yahan bhi 'virtual' lagaya

class CodeTeacher : public Engineer, public Youtuber {
    CodeTeacher(string name, ...) {
        this->name = name;   // ✅ Ab koi ambiguity nahi — sirf EK copy hai
    }
};
```

**`virtual` Keyword Kya Karta Hai:** Jab `Engineer` aur `Youtuber` dono `Human` ko **`virtual`** keyword ke saath inherit karte hain, to C++ ko pata chal jaata hai — *"Human ki ek se zyada copies mat banana, jab bhi koi diamond structure mein isse inherit kare, to sabko EK HI SHARED copy do."*

```
                    Human
                (SIRF EK SHARED COPY)
               /                  \
          Engineer              Youtuber
               \                  /
                 \               /
                  CodeTeacher
           (name — sirf EK hi, koi ambiguity nahi)
```

**Analogy:** Ye aisा hai jaise Dada ki ghadi ko **ek "family shared vault"** mein rakh diya jaaye — Papa aur Chacha dono **usi ek hi asli ghadi ko refer** karte hain (apna-apna alag copy nahi banate). Ab jab tum (CodeTeacher) "Dada ki ghadi" maango, to koi confusion nahi — **ek hi ghadi hai**, sabne usi ko share kiya hua hai.

---

### 6.3 Tumhare Code Ka Final Flow

```cpp
class CodeTeacher : public Engineer, public Youtuber {
public:
    int salary;
    CodeTeacher(string name, string specilization, int subscriber, int salary) {
        this->name = name;                    // ab clear hai, sirf EK 'name' hai (virtual ki wajah se)
        this->specilization = specilization;
        this->subscriber = subscriber;
        this->salary = salary;
    }
};

int main() {
    CodeTeacher A1("yash", "CSE", 1e8, 1e8);
    A1.display();   // Output: My name is yash
}
```

## PART 7: FULL RECAP TABLE (Interview-Ready)


| Type                    | Structure                                                 | Kab Use Hota Hai                                        | Special Care                                                                          |
| ----------------------- | --------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **Single Level**        | Parent → Child                                           | Simple "IS-A" relationship                              | Function Hiding ka dhyan rakho                                                        |
| **Multilevel**          | Grandparent → Parent → Child                            | Layered hierarchy (jaise Person → Employee → Manager) | Constructor chain order (Grandparent se shuru)                                        |
| **Multiple**            | 2 unrelated Parents → 1 Child                            | Jab do alag-alag capabilities combine karni ho          | Dono base constructors declaration order mein call hote hain                          |
| **Hierarchical**        | 1 Parent → multiple Children                             | Common base, alag specializations                       | Agar khud constructor likha to Base ka default constructor bhi explicitly likhna pade |
| **Hybrid**              | Multiple types ka mix                                     | Real-world complex relationships                        | Sabhi individual types ke rules apply hote hain                                       |
| **Multipath (Diamond)** | Grandparent → 2 Parents → wapas 1 Child mein milte hain | Jab common ancestor do paths se aa raha ho              | **`virtual`inheritance zaroori**warna Ambiguous Error                                 |

---

## PART 8: FINAL ONE-LINE SUMMARY

* **Single** = Ek se ek.
* **Multilevel** = Chain (dada→papa→beta).
* **Multiple** = Do alag parents ek child mein milte hain.
* **Hierarchical** = Ek parent, kai bachche.
* **Hybrid** = Upar walon ka mix.
* **Multipath (Diamond)** = Common ancestor do raaston se aata hai → `virtual` keyword se duplicate copy problem solve karo.
