---

# PART A: INHERITANCE

## A.1 Inheritance Kya Hai?

**Definition (tumhare code mein diya gaya):***"The capability of a class to derive properties & characteristics from another class."*

Matlab — ek class (**Derived/Child class**) doosri class (**Base/Parent class**) ke **data members aur member functions ko reuse** kar sakti hai, bina unhe dobara likhe.

**Analogy:** Inheritance bilkul **family property/traits** jaisa hai — ek bacha (Child class) apne parents (Base class) se kuch **properties automatically paata hai** (jaise ghar, ankhon ka rang) bina khud kamaye/banaye. Bacha apni **extra khud ki cheezein** bhi add kar sakta hai (jo uske parents ke paas nahi thi).

```cpp
class Human {                // Base / Parent Class
public:
    string name;
    int age, weight;
};

class Student : private Human {   // Derived / Child Class — Human se inherit kar raha hai
private:
    int fees, roll_no;       // ye Student ki APNI khud ki extra properties hain
};
```

`Student` class ko `name`, `age`, `weight`**dobara likhne ki zaroorat nahi padi** — `Human` se already mil gaye. Sirf apni extra cheezein (`fees`, `roll_no`) add ki.

---

## A.2 Inheritance Kyu Use Karte Hain?

1. **Code Reusability** — same code baar-baar na likhna pade.
2. **Real-world Relationship Modelling** — "Student IS-A Human", "Teacher IS-A Human" — ye natural hierarchy represent karta hai.
3. **Maintainability** — agar `Human` mein kuch change karna ho (jaise ek naya common field add karna), to sirf **ek jagah** change karo, saari derived classes (`Student`, `Teacher`) ko automatically mil jaayega.

**Analogy:** Ye aisа hai jaise ek **common "template" (Base class)** bana lo jisme sabke liye shared cheezein ho, aur har specific type (Student, Teacher, Doctor) apna alag "add-on" laga le — bina base template ko baar-baar dobara banaye.

---

## A.3 Base Class vs Derived Class — Terminology


| Term                                        | Matlab                                            |
| ------------------------------------------- | ------------------------------------------------- |
| **Base Class / Parent Class / Super Class** | Jisse properties**li**ja rahi hain (`Human`)      |
| **Derived Class / Child Class / Sub Class** | Jo properties**le**raha hai (`Student`,`Teacher`) |

```cpp
class Student : private Human   // ": private Human" -> "Student, Human se inherit kar raha hai"
```

# PART B: ACCESS MODIFIERS — DEPTH MEIN (BEFORE Inheritance)

Pehle basic access modifiers revise karte hain (tumne khud table banayi thi, wo bilkul sahi hai):


| Modifier    | External Code Se Access | Same Class Ke Andar | Derived Class Mein |
| ----------- | ----------------------- | ------------------- | ------------------ |
| `public`    | ✅ Yes                  | ✅ Yes              | ✅ Yes             |
| `protected` | ❌ No                   | ✅ Yes              | ✅ Yes             |
| `private`   | ❌ No                   | ✅ Yes              | ❌ No              |

### B.1 `public`

Har jagah se access ho sakta hai — class ke andar, class ke bahar, derived class mein bhi.

### B.2 `private`

**Sirf usi class ke andar** access ho sakta hai jisme declare hua hai — na bahar se, na derived class se (chahe kitni bhi inheritance ho).

### B.3 `protected`

**`private` jaisa hi hai class ke bahar ke liye** (bahar se access nahi), **lekin ek extra permission hai** — **Derived class ke andar (member functions se) access ho sakta hai**, jo `private` allow nahi karta.

**Analogy — Ek Ghar (Class):**

* **`public`** = Ghar ka **main gate/living room** — koi bhi aa sakta hai.
* **`protected`** = Ghar ka **family-only area** — bahar wale nahi aa sakte, lekin **ghar ke bacche/grandchildren (derived classes)** aa sakte hain.
* **`private`** = Ghar ka **personal bedroom (sirf uss ghar walo ka)** — chahe grandchildren bhi ho, unhe bhi andar jaane ki permission nahi (sirf jo isi ghar mein paida hue, wahi jaa sakte hain — dusri generation nahi).

# PART C: INHERITANCE TYPE (Public/Protected/Private Inheritance) — VERY IMPORTANT

Ab yahan **do cheezein combine** hoti hain, jahan confusion hota hai:

1. Base class mein member kis access modifier ka hai (`public`/`protected`/`private`)
2. **Inheritance khud kis type ki hai** (`class Student : public Human` / `: protected Human` / `: private Human`)

**Inheritance type batata hai — Base class ke `public` aur `protected` members, Derived class mein AAKE kis access level ke ban jaayenge.**

---

## C.1 THE MASTER TABLE (Saare Combinations — Yahi Sabse Important Hai)


| Base Class Mein Member Kaisa Tha ↓ | `public`Inheritance                                                                                | `protected`Inheritance               | `private`Inheritance               |
| ----------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------ | ---------------------------------- |
| `public`                            | Derived mein**public**rahega                                                                       | Derived mein**protected**ban jaayega | Derived mein**private**ban jaayega |
| `protected`                         | Derived mein**protected**rahega                                                                    | Derived mein**protected**rahega      | Derived mein**private**ban jaayega |
| `private`                           | Derived class mein**accessible hi nahi**(inherited to hota hai, par directly touch nahi kar sakte) | (same) accessible nahi               | (same) accessible nahi             |

### Isse Yaad Rakhne Ka Simple Tareeka:

> **"Inheritance type NEVER access ko upgrade (loosen) karta, sirf same rakh sakta hai ya aur tight (restrict) kar sakta hai."**

* `public` inheritance = **sabse "generous"** — Base ke members apna original access level **maintain** karte hain (public→public, protected→protected).
* `protected` inheritance = **thoda restrict** karta hai — Base ka `public` bhi **protected** ban jaata hai.
* `private` inheritance = **sabse "tight"** — Base ka `public` aur `protected` dono **private** ban jaate hain.
* `private` member **hamesha hidden** rehta hai derived class se, chahe inheritance kisi bhi type ki ho.

**Analogy — "Downgrade Only" Rule:** Socho har member ki ek **"VIP level"** hai — Public = General Pass, Protected = Family Pass, Private = Sabse Restricted (koi pass nahi). Jab inheritance hoti hai, to **pass kabhi upgrade nahi ho sakta, sirf downgrade ho sakta hai** (ya same rahe):

* **`public` inheritance** = koi bhi pass downgrade nahi hota (jaisa tha waisa hi rehta hai)
* **`protected` inheritance** = General Pass bhi ab **Family Pass** ban jaata hai (thoda restrict ho gaya)
* **`private` inheritance** = General aur Family Pass, dono **"No Entry (private)"** ban jaate hain

## C.2 Tumhare Code Ka Analysis (`class Student : private Human`)

```cpp
class Human {
    string Religion, color;   // (default) private — Human class ke andar hi accessible

public:
    string name;
    int age, weight;          // public members
};

class Student : private Human {   // PRIVATE INHERITANCE
private:
    int fees, roll_no;
};
```

**Table se maanchte hain:**

* `Human` ke `public` members (`name`, `age`, `weight`) → `private` inheritance ki wajah se → **`Student` class ke andar `private` ban gaye.**
* `Human` ke `Religion`, `color` (jo `private` hain) → **`Student` mein bilkul accessible nahi** (chahe inheritance kisi bhi type ki ho).

**Isliye tumhare `display()` function mein `name`, `age`, `weight` access ho paaye:**

```cpp
void display() {
    cout << name << " , age is " << age << " weight is " << weight << ...;
    // Ye chal raha hai kyunki private inheritance ke baad bhi 'name/age/weight'
    // STUDENT CLASS KE ANDAR (private ban ke) accessible hain — bas class ke BAHAR se nahi.
}
```

**Lekin `main()` se ye kabhi nahi chalega:**

```cpp
int main() {
    Student A("yash", 20, 3000, 23, 83883);
    A.name = "yash";     // ❌ ERROR! 'name' Student class ke bahar se PRIVATE ho chuka hai (private inheritance ki wajah se)
}
```

**Tumhara code comment bilkul sahi diagnosis tha:***"Base class se private aaye aur derived mein public ho to kaise treat hoga"* — is table se ab clear hai ki **kabhi bhi upgrade nahi hota**, sirf same ya downgrade hota hai.

## C.3 Ek Aur Example — Teacher Class (Default Inheritance)

```cpp
class Teacher : Human {   // ": Human" bina keyword ke -> class ke liye DEFAULT hota hai "private"
    int salary, id;
};
```

**Important C++ Rule:** Agar tum `class` keyword use karte ho aur inheritance type likhna **bhool jao**, to C++ **default `private` inheritance** maan leta hai. (Agar `struct` use karte to default `public` hota — ye ek common interview trick question hai!)

```cpp
class Teacher : Human { };     // same as: class Teacher : private Human { }
struct TeacherS : Human { };   // same as: struct TeacherS : public Human { }
```

## C.4 Full Example — Teeno Inheritance Types Ka Comparison

```cpp
class Human {
private:
    string religion;    // NEVER accessible in any derived class
protected:
    string bloodGroup;  // becomes protected/protected/private depending on inheritance
public:
    string name;        // becomes public/protected/private depending on inheritance
};

class A : public Human {
    // name -> public, bloodGroup -> protected, religion -> not accessible
};

class B : protected Human {
    // name -> protected, bloodGroup -> protected, religion -> not accessible
};

class C : private Human {
    // name -> private, bloodGroup -> private, religion -> not accessible
};

int main() {
    A a1;
    a1.name = "Yash";     // ✅ OK — public inheritance mein name public hi raha

    B b1;
    b1.name = "Yash";     // ❌ ERROR — protected inheritance mein name ab protected ban gaya, bahar se access nahi

    C c1;
    c1.name = "Yash";     // ❌ ERROR — private inheritance mein name ab private ban gaya, bahar se access nahi
}
```

## C.5 Kab Kaunsi Inheritance Use Karein?


| Inheritance Type | Kab Use Karein                                                                                                                                                                                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `public`         | **Sabse common**— jab tum "IS-A" relationship chahte ho jahan derived class ka user, base class ke public members ko bhi wahi access level mein use kar sake. Jaise`Student IS-A Human`, aur`Student`ka user`name`field ko dekh sake.                                                      |
| `protected`      | Jab tum chahte ho ki base ke members sirf**derived classes ki further hierarchy**mein hi accessible rahein, bahar koi na use kare. Kam use hota hai.                                                                                                                                        |
| `private`        | Jab tum "IS-A" nahi balki**"IMPLEMENTED-USING" (has-a jaisa internal use)**relationship chahte ho — matlab`Student` **internally** `Human`ka code reuse kar raha hai, lekin`Student`ka user ye jaan bhi na paaye ki`Student`,`Human`se inherit ho raha hai. Sabse restrictive, kam common. |

**Analogy:**

* **`public` inheritance** = "**Student IS-A Human**" — jo bhi ek Human kar sakta hai, Student bhi wahi (kam se kam) kar sakta hai, khule tareeke se.
* **`private` inheritance** = "**Student INTERNALLY USES Human's code**" — jaise ek car engine internally kuch reusable parts use karta hai, lekin driver (external user) ko in internal parts se seedha kuch lena-dena nahi.

## PART D: QUICK RECAP TABLE (Interview-Ready, Ek Nazar Mein)

### Basic Access Modifiers:


| Modifier    | Class Ke Andar | Derived Class | Class Ke Bahar |
| ----------- | -------------- | ------------- | -------------- |
| `private`   | ✅             | ❌            | ❌             |
| `protected` | ✅             | ✅            | ❌             |
| `public`    | ✅             | ✅            | ✅             |

### Inheritance Type Ke Saath Combination (THE MASTER RULE):


| Base Member | `public`Inheritance | `protected`Inheritance | `private`Inheritance |
| ----------- | ------------------- | ---------------------- | -------------------- |
| `public`    | public              | protected              | private              |
| `protected` | protected           | protected              | private              |
| `private`   | not accessible      | not accessible         | not accessible       |

### Extra Rules:

* `class` ke liye default inheritance = **`private`**; `struct` ke liye default = **`public`**.
* Access **kabhi upgrade nahi hota** inheritance ke through, sirf same ya restrict (downgrade) hota hai.
* `private` member **kabhi bhi** derived class mein direct accessible nahi hota, chahe inheritance kisi bhi type ki ho.
